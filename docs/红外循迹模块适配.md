# 红外循迹模块适配

## 接口结论

采用 **I2C 400 kHz**，不采用串口。

| 对比项 | I2C | 串口 |
| --- | --- | --- |
| 单次数字量 | 读 `0x30` 得到 1 字节 | `$D,x1:0,...,x8:0#`，约 43 字节 ASCII |
| 线上时间 | 约 40 个时钟，约 0.1 ms | 115200-8-N-1 下约 3.7 ms/帧 |
| CPU 工作 | 中断搬运 1 B，无文本解析 | 逐字节接收、找帧、检查字段并解析字符 |
| 新增资源 | 独占 I2C1 和 PA15/PA16 | 需要额外 UART 和引脚；当前 UART0/1/3/7 均有用途 |
| 更新控制 | 主控按需以 2 ms 周期读取 | 依赖模块主动上报周期，可能积压旧帧 |
| 扩展能力 | 同一总线可挂不同地址设备 | 点对点，新增设备通常再占 UART |

串口在长线、异步主动上报和无需共享总线仲裁时更合适；本车短距离、只消费 8 位实时数字状态，I2C 的传输量、内存和中断开销都更小。

## 实现策略

- `i2c_bus` 分别管理 OLED 的 I2C0 和红外模块的 I2C1 ISR，提供写和写后读的非阻塞事务。
- 红外模块每 2 ms 请求寄存器 `0x30`。
- 红外 I2C1 中断优先级高于 OLED I2C0；两者可独立运行，不存在 OLED 长帧阻塞循迹读取的问题。
- 保留 `grayscale_get_values()` 和 `grayscale_get_scan_sequence()`，循迹控制与 OLED 显示无需修改。
- I2C NACK、仲裁丢失或 10 ms 超时会释放总线；控制层原有 30 ms 新鲜度保护会停车。

## 接线与协议

- 模块地址：`0x12`（7 位）
- 数字量寄存器：`0x30`
- 位序：X1=bit7，X2=bit6，...，X8=bit0
- VCC：5V（官方接线）；SCL：PA15；SDA：PA16；独占 I2C1，与 OLED 仅共地
- SDA/SCL 上拉电压不得高于 3.3V；模块若上拉到 5V，需改上拉或加双向电平转换

官方例程的校准寄存器 `0x01` 未在启动时自动写入，避免每次上电无条件改变模块标定。需要校准时应由明确的维护命令触发，而不是放入实时循迹路径。
