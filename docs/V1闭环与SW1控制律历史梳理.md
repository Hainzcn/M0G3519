# V1 闭环与 SW1 控制律历史梳理

## 1. 范围、命名与结论

检查范围包括：

- `M0G3519/main` 从 `c484ff8` 到 `38915b2` 的 8 个主线提交；
- 从 `c429127` 分出的 `dev01` 提交 `c206408`；
- 当前工作树中尚未提交的 V2 重构草案。

核心结论如下：

1. 历史 V1 从“回中 PD”逐步演进为“轨迹前馈 + 位置/速度反馈”，最后变成显式
   位置-速度串级闭环。它不是直接输出电机角，而是先求钢球期望加速度，再通过滚球
   逆动力学、角度限幅、摆杆轨迹和连杆逆解得到 Emm42 位置命令。
2. 已提交历史中的 SW1 不是独立控制律。它只是把闭环参考位置依次设为 `+0.05 m`
   和 `-0.05 m`，V1 与 SW1 共用同一个估计器、轨迹规划器和反馈控制器。
3. 当前未提交 V2 草案改变了定义：V1 变为离散角度的加速/滑行/制动回中闭环；SW1
   变为完全不依赖视觉反馈的六段绝对时间开环。两套控制器互斥，只共享执行器和
   边缘安全监视。
4. 因此，讨论“SW1 控制律”时必须注明版本。`38915b2` 及以前是闭环轨迹模式；当前
   工作树才是纯时间开环模式。

## 3. 已提交版本的共同控制链

### 3.1 坐标、状态估计与测量有效性

历史版本以球位置 `x`、球速度 `v`、摆杆角 `theta` 和车体规划加速度 `a_car` 为
主要状态。估计器以 5 ms 周期运行，并在新视觉帧到达时吸收测量；状态模型采用实心球
无滑动滚动系数 `k=5/7`：

```text
a_model = -(5/7) * (g*sin(theta) + a_car*cos(theta))
x_hat   = x_hat + v_hat*dt + 0.5*a_model*dt^2
v_hat   = v_hat + a_model*dt
```

新视觉帧到来后不是直接覆盖估计值，而是按固定增益校正：

```text
x_hat = x_hat + 0.65*(x_meas - x_hat)
v_hat = v_hat + 0.50*(v_meas - v_hat)
```

测量年龄不超过 `30 ms` 时为正常闭环；`30~80 ms` 只做模型预测且摆角限幅由
`±4 deg` 收紧为 `±2 deg`；超过 `80 ms` 进入恢复并回水平。有效视觉还必须同时满足
测量有效、跟踪器就绪、标定有效和置信度不低于 50。`f1960b9` 起，位置会按视觉处理
耗时加 `3 ms` 串口耗时前推，补偿上限为 `30 ms`。

### 3.2 从钢球加速度到摆杆角

闭环先求期望钢球加速度 `a_cmd`，然后对滚球模型做逆解：

```text
R       = sqrt(g^2 + a_car^2)
theta   = asin(-a_cmd / ((5/7)*R)) - atan2(a_car, g)
```

随后依次执行：

- `a_cmd` 限制在 `±0.45 m/s²`；
- 新鲜视觉下 `theta` 限制在 `±4 deg`，降级预测时限制在 `±2 deg`；
- 摆杆目标按 `30 deg/s` 限速；`33757c9` 起增加 `600 deg/s²` 加速度限制；
- 连杆逆解将逻辑摆杆角换算成电机轴绝对角；
- `BALANCE_CONTROL_OUTPUT_SIGN=-1`、`BALANCE_LINKAGE_TARGET_SIGN=-1` 和
  `BALANCE_EMM42_DIRECTION_SIGN=-1` 分别处理闭环响应、连杆坐标和电机安装方向。

三层符号用途不同，不能通过相乘后的结果把宏合并，否则回水平、Demo 和闭环方向会
失去独立标定能力。

### 3.3 安全覆盖

历史主线中的常规控制会被边缘逻辑覆盖：

- `|x_hat|>=100 mm`：期望加速度改为指向中心的固定 `0.22 m/s²`；
- `|x_hat|>=125 mm` 且持续 `200 ms`：锁存硬边缘故障；
- 初版硬边界为 `115 mm`，`c429127` 和 `33757c9` 放宽到 `150 mm`，`644b177`
  最终收紧到 `125 mm`；
- 视觉超过 `80 ms`、链路离线或执行器连续命令错误时退出活动控制并回水平；
- 电机目标与反馈误差超过 `5 deg` 持续 `1 s` 才锁存跟随故障。

## 4. 历史 V1 闭环控制律

### 4.1 第一阶段：固定中心 PD（`c484ff8` 至 `33757c9`）

目标固定为物理中心 `x_ref=0`，控制律为：

```text
e_x   = -x_hat
a_cmd = Kp*e_x - Kd*v_hat
```

参数经历两次主要调整：

- `c484ff8`、`012c2e2`：`Kp=8`，`Kd=4`；
- `c429127`、`33757c9`：`Kp=4`，`Kd=1.8`。

这是一条以钢球加速度为输出的 PD，而不是“角度 PD”。角度由上一节的逆动力学求得。
`33757c9` 将 200 Hz 状态估计和 50 Hz 外环输出分开，并优先使用 Emm42 反馈换算的
实际摆杆角进行模型预测；这降低了把命令角误当实际角造成的状态预测误差。

### 4.2 第二阶段：轨迹前馈 + PD（`644b177` 至 `479d86c`）

加入梯形球轨迹后，V1 回中和 SW1 往返统一采用：

```text
e_x   = x_ref - x_hat
e_v   = v_ref - v_hat
a_cmd = Ka*a_ref + Kp*e_x + Kd*e_v
```

其中 `x_ref/v_ref/a_ref` 由 `ball_motion_profile` 在 200 Hz 更新。规划器以
`v_ref^2/(2*a_brake)` 判断制动距离，并具有 `ACCEL/CRUISE/BRAKE/HOLD` 阶段。

`644b177` 的起始参数为：

```text
Kp=4, Kd=1.8, Ka=0.5
a_drive=0.08 m/s², a_brake=0.10 m/s², vmax=0.05 m/s
brake_margin=0.010 m
```

固定 `10 mm` 制动裕量导致轨迹过早制动并在加速/制动之间反复切换，单个
`O→+5 cm` 仿真约需 `6.2 s`，超过软件期望。`f1960b9` 因此删除固定裕量并锁存
制动阶段，同时改为：

```text
Kp=8, Kd=4, Ka=1.0
a_drive=0.12 m/s², a_brake=0.16 m/s², vmax=0.075 m/s
```

同一提交还把有效变化的执行器命令从 10 Hz 提高到 50 Hz，接入
`a_car`（增益/符号均为 1，限幅 `±2 m/s²`）。`479d86c` 随后为减小过激反馈，把
`Kp/Kd` 降到 `3/1.5`，把轨迹限速降到 `0.060 m/s`，并增加 `120 ms` 制动前视。

### 4.3 第三阶段：位置-速度串级（`38915b2`）

最终已提交版本把位置误差显式转换成有限速度命令：

```text
e_x   = x_ref - x_hat
v_cmd = clamp(v_ref + Kx*e_x, -0.060, +0.060)
a_cmd = Ka*a_ref + Kv*(v_cmd - v_hat) + a_friction
```

其中：

```text
Kx = 2.0 s^-1
Kv = 2.0 s^-1
Ka = 1.0
```

未触发速度限幅时，等效反馈为 `Kp=Kx*Kv=4`、`Kd=Kv=2`；大扰动时由
`±0.060 m/s` 的 `v_cmd` 限幅约束回中速度。低速摩擦补偿只在参考轨迹已经
`HOLD`、`|e_x|>4 mm` 且 `|v_hat|<10 mm/s` 时加入，幅值为 `0.045 m/s²`，方向与
`v_cmd` 相同。总加速度仍受 `±0.45 m/s²` 限制。

## 5. 已提交版本的 SW1 模式

### 5.1 模式本质

SW1 调用 `balance_app_start_sequence()`，只改变轨迹目标，不绕过反馈：

```text
当前估计状态 -> 目标 +0.050 m -> 到达并稳定 -> 目标 -0.050 m -> 保持
```

所以历史 SW1 的每一时刻仍执行第 4 节的闭环控制律。它使用视觉位置/速度、状态估计、
轨迹前馈、边缘保护、车体加速度前馈和执行器限幅。称其为“开环 SW1”是不准确的。

### 5.2 到达判据与超时演进

每段到达要求同时满足：

```text
轨迹阶段 == HOLD
|x_target-x_hat| <= 6 mm
|v_hat| <= 0.030 m/s
持续 100 ms
```

`644b177` 中完整往返共用一个起始时刻，累计 `4800 ms` 超时即取消流程并回中。
`38915b2` 根据实测
“正向仅到约 37~39 mm”修改为分腿计时：正向腿到达或超时都进入负向腿，只有负向腿
超时才取消并回零。这提高了流程完成概率，但也意味着“正向腿完成”不再等价于到达
`+50 mm`，遥测分析必须同时检查 sequence state 与实际位置。

视觉丢失、恢复态或锁存故障会立刻取消历史 SW1，并把目标改回中心。因此它不具备在
视觉失效时继续按预定时间运行的能力。

## 6. 当前未提交 V2 草案

本节仅描述检查时的工作树，不属于任何历史提交；后续代码仍可能变化。

### 6.1 V1：基于制动距离的离散角闭环

V1 不再构造连续 `a_cmd`，也不再使用 MCU 帧间状态积分、位置-速度串级、球参考轨迹
或车体加速度前馈。控制器只在新视觉测量到来时根据状态机选择离散摆角。

若球在负侧，锁存 `direction=+1`，向正方向回中；若球在正侧，锁存
`direction=-1`。定义：

```text
u         = max(direction*v, 0)
remaining = max(direction*(-x), 0)
d_stop    = 0.003 + 0.22*u + u^2/(2*a_brake)
```

两方向参数不对称，用于吸收机构和摩擦差异：

| 回中方向 | 加速角偏置 | 制动角偏置 | 标称制动减速度 |
|---|---:|---:|---:|
| `direction=+1`（球从负侧回中） | `-1.0 deg` | `+1.1 deg` | `0.14 m/s²` |
| `direction=-1`（球从正侧回中） | `+0.8 deg` | `-0.6 deg` | `0.08 m/s²` |

状态转换为：

```text
WAIT_VISION -> ACCEL -> CRUISE -> BRAKE -> SETTLE -> HOLD
```

- `u>=0.060 m/s`：`ACCEL→CRUISE`，输出中性角；
- `CRUISE` 中 `u<0.050 m/s`：允许回到 `ACCEL`；
- `remaining<=d_stop`：进入 `BRAKE`，本次动作不再回到加速；
- `u<=0.005 m/s`：进入 `SETTLE`；
- `|x|<=3 mm` 且 `|v|<=5 mm/s` 持续 `100 ms`：进入 `HOLD`；
- `HOLD` 中 `|x|>=5 mm` 或 `|v|>=10 mm/s`：重新规划回中；
- 单次捕获超过 `5000 ms`：锁存 V1 捕获超时；
- 测量年龄超过 `100 ms`：立即输出中性角，连续 3 个有效新帧后重新规划。

这里的“闭环”是视觉状态驱动的分段/继电式闭环，不再是线性 PD 或串级反馈。

### 6.2 SW1：六段绝对时间纯开环

当前 SW1 首次角度命令成功下发后锁存统一起点，所有截止时间都由该起点累计，命令
延迟不会把后续阶段整体顺延：

| 阶段 | 目标角 | 持续时间 | 累计截止时间 |
|---|---:|---:|---:|
| 正向加速 | `-1.0 deg` | `900 ms` | `900 ms` |
| 正向制动 | `+1.1 deg` | `520 ms` | `1420 ms` |
| 换向停顿 | `0.0 deg` | `200 ms` | `1620 ms` |
| 负向加速 | `+0.8 deg` | `820 ms` | `2440 ms` |
| 负向制动 | `-0.6 deg` | `1220 ms` | `3660 ms` |
| 最终稳定 | `0.0 deg` | `200 ms` | `3860 ms` |

其数学表达就是分段常值输入 `theta_cmd(t)`，没有 `x`、`v` 或误差项。任一阶段命令
比绝对截止时间晚超过 `50 ms`，或总运行达到 `4800 ms`，都会请求中性角并锁存故障。
正常完成后保持 `0 deg` 和 `SW1_COMPLETE`，不会自动切回 V1。

视觉丢失不影响 SW1 的时间序列，但安全监视器仍检查新鲜视觉：`|x|>=120 mm` 时取消
SW1并进入 V1 边缘恢复；若 `500 ms` 内位置绝对值没有至少改善 `5 mm`，则锁存边缘
无进展故障。`100 mm` 为软边缘标志，不直接打断序列。

## 8. 评审与调参注意事项

1. 日志、报告和验收记录必须附带提交号；只写“V1”或“SW1”无法唯一确定控制律。
2. 当前 V2 SW1 的四个角度与 V1 两方向的加速/制动角完全相同，但两者不是同一种
   控制：V1 用视觉决定切换时刻，SW1 用固定累计时间决定切换时刻。
3. 历史串级版本应先调速度内环，再调位置外环；当前 V2 V1 应只调两方向制动减速度、
   延迟项和停车余量，二者的调参方法不能混用。
4. 当前 SW1 建议先以 `20 ms` 步进调整四段脉冲时长，再以 `0.1 deg` 步进调整四个
   角度。每次都应检查阶段是否在 `50 ms` 容差内下发，以及硬边缘监视是否触发。
5. `BALANCE_STARTUP_LEVER_ANGLE_DEG=-5 deg` 是机械负限位参考，不是 V1/SW1 的工作
   摆角；水平工作点仍定义为 `0 deg`。
6. 摆杆 IMU 在上述所有版本中都未进入正式闭环，仅用于诊断；没有完成方向、比例、
   零偏和线加速度影响标定前，不应把它作为反馈量接入。

## 10. 视觉到电机响应的端到端延迟预算

本节区分三个终点，避免把通信应答、开始运动和机械到位混为同一个“响应时间”：

```text
T_command：物理位置变化 -> Emm42 收到完整位置命令
T_onset：  物理位置变化 -> 电机/摆杆开始产生可测运动
T_settle： 物理位置变化 -> 摆杆进入目标角允许误差
```

### 10.1 视觉采样与识别频率

MaixCAM2 发送端配置为 `640x480 @ 60 FPS`，理论帧周期为 `16.67 ms`，摄像头缓冲
数量为 3。识别循环每取得一帧就运行透视校正/小球跟踪并立即发送一条 24 字节状态
帧，没有单独的下发限频器。

历史实车日志中，MCU 观察到的视觉序列更新间隔中位数为 `20 ms`，95 分位通常为
`30~40 ms`。该数据受 MCU 10 ms 遥测采样量化影响，但足以说明实际稳定输出约为
`50~60 Hz`，偶发处理慢帧会降到 `25~33 Hz`。首次从完全丢球状态捕获还要求连续两帧
确认，因此首次有效位置比稳态跟踪额外晚约一个视觉周期，即约 `17~40 ms`。

需要特别注意时间戳的含义：`timestamp_ms` 在调用 `cam.read()` 之前取得；协议里的
`processing_ms` 只累计小球跟踪和透视处理，不包括：

- 等待下一帧或从摄像头缓冲取帧；
- 相机曝光、读出和 ISP；
- `image2cv()` 图像格式转换；
- `serial.write()` 自身耗时。

因此 MCU 使用的 `processing_ms + 3 ms` 只是一部分延迟。代码将它限制在 `30 ms`
以内并按球速前推位置，但无法补偿相机缓冲中的旧帧。最近多数历史日志中新视觉帧
首次进入控制时，记录的 `vision_age_ms` 中位数约 `25 ms`、95 分位约 `30~33 ms`；
这些数值是“软件可见年龄”，不能直接当作曝光到 MCU 的真实延迟。

### 10.2 各环节延迟拆分

在 `115200-8-N-1` 下，每字节占 10 bit。由此可以精确得到两段串口线上时间：

```text
24 B 视觉帧：24*10/115200 = 2.08 ms
13 B 位置命令：13*10/115200 = 1.13 ms
 4 B 命令应答： 4*10/115200 = 0.35 ms
```

| 环节 | 典型估计 | 健康链路上界/风险 | 依据 |
|---|---:|---:|---|
| 物理变化等待下一次相机采样 | `0~16.7 ms`，平均约 `8.3 ms` | 慢帧时 `20~40 ms` | 60 FPS 配置及实车序列间隔 |
| 曝光、读出、ISP、取帧缓冲 | 约 `16.7 ms` | 三缓冲积压时可能 `33~50 ms` | 缓冲数为 3；驱动策略未实测 |
| 图像转换、透视与小球识别 | 约 `15~25 ms` | 约 `30 ms` 或更高 | 历史 `vision_age_ms` 反推；格式转换未计入上报值 |
| MaixCAM2 -> MCU UART3 | `2.08 ms` | `2.08 ms` | 24 B、115200 baud |
| MCU 收帧解析与 V1 规划 | 通常 `<1 ms` | 一个主循环；无硬实时上界 | 同一主循环先解析视觉、随后运行 `balance_app` |
| 等待 UART7 可下发 | 通常 `0~3 ms` | 已有命令/查询未应答时可接近 `25 ms` | 单命令 pending，位置查询周期 100 ms，应答超时 25 ms |
| MCU -> Emm42 UART7 | `1.13 ms` | `1.13 ms` | 13 B、115200 baud |
| Emm42 解帧到内部位置环采用目标 | 暂估 `1~5 ms` | 未知 | 仓库无驱动器内部控制周期或实测数据 |

当前 V2 V1 只在新视觉帧到来时重新规划，但规划完成后在同一主循环立即尝试下发角度，
没有额外固定的 5 ms 或 20 ms 调度周期。若 UART7 正在等待移动命令 ACK 或 100 ms
位置查询返回，`lever_actuator_command_angle()` 会返回 `BUSY`，直至下一次新视觉帧
再次尝试，故一次冲突通常还会增加一个 `17~40 ms` 视觉周期。历史 `33757c9` 至
`38915b2` 则有 50 Hz 外环，最坏还需额外等待 `20 ms`。

### 10.3 合计预算

根据上表，当前 V2 可先采用以下工程预算，而不能视作已验证指标：

| 端点 | 典型预算 | 保守健康上界 | 说明 |
|---|---:|---:|---|
| 物理位置变化 -> Emm42 收到位置命令 | `40~65 ms` | `90~125 ms` | 包含等待下一帧；缓冲积压和 pending 冲突是主要长尾 |
| 物理位置变化 -> 电机开始运动 | `45~70 ms` | `100~130 ms` | 在上一项上暂加 `1~5 ms` 驱动内部采用时间 |
| 物理位置变化 -> 摆杆基本到位 | `90~180 ms` | `150~250 ms` | 还包含加减速、机构惯量、间隙和负载，必须实测 |

如果从“某一帧已经完成曝光”开始计时，而不是从任意物理变化开始，第一行的平均
`8.3 ms` 等待采样可以去掉。反之，如果关注小球真实运动到摆杆产生有效倾角的完整
闭环，还需叠加电机运动起始后的机构间隙与摆杆建力时间。

### 10.4 电机内部闭环与机械运动下界

当前 Emm42 位置命令使用 `30 RPM` 和加速度档位 `20`。`30 RPM` 等于电机轴
`180 deg/s`。按当前连杆逆解，SW1 各阶段的电机轴目标约为：

| 摆杆目标 | 电机轴目标 | 相对上一阶段的电机轴行程 | 仅按 30 RPM 计算的最短匀速时间 |
|---:|---:|---:|---:|
| `-1.0 deg` | `-22.54 deg` | 从中性 `4.30 deg` | `23.9 ms` |
| `+1.1 deg` | `-13.73 deg` | `8.81 deg` | `49.0 ms` |
| `0.0 deg` | `-18.24 deg` | `4.51 deg` | `25.1 ms` |
| `+0.8 deg` | `-14.93 deg` | `3.31 deg` | `18.4 ms` |
| `-0.6 deg` | `-20.80 deg` | `5.87 deg` | `32.6 ms` |
| `0.0 deg` | `-18.24 deg` | `2.56 deg` | `14.2 ms` |

这些只是速度上限给出的理论下界。加速度档位 `20` 在仓库中没有对应到
`deg/s²` 或加速时间的标定，Emm42 内部位置环周期、跟随误差、负载惯量和机构间隙也
未知，所以不能从代码可靠计算实际到位时间。历史遥测每 `100 ms` 才查询一次电机
位置；日志中目标变化到首次观察到反馈变化的中位数约 `50~70 ms`，主要反映查询
相位和采样量化，不能证明电机本体存在同样大的纯延迟。

### 10.5 建议的实测方法

要把上述区间收敛为可用于制动距离的参数，建议一次采集四个同步时间点：

1. 用 LED 阶跃或带时间标记的移动靶产生可见位置变化，避免两块处理器时钟不同步；
2. MaixCAM2 在取得帧、识别完成和 UART 写入前分别翻转 GPIO；
3. MCU 在 CRC 正确帧解析完成、规划完成和 UART7 首字节发送时分别翻转 GPIO；
4. 用外部编码器、激光位移计或电机 STEP/电流信号记录电机开始运动和摆杆到位时刻；
5. 逻辑分析仪同时采 GPIO、UART3、UART7 和运动传感器，至少统计 200 次的中位数、
   95 分位和最大值。

仅依赖现有 100 ms 电机位置查询无法分辨 `1~100 ms` 范围内的电机起动延迟。实测后
应把 V1 制动公式中的 `brake_delay_s=0.22 s` 拆成“视觉/通信纯延迟”和“执行器/滚球
制动动态”两部分核对；当前 `0.22 s` 明显大于上述命令链典型延迟，包含了机械及钢球
动态裕量，不应直接解释为串口或电机内部闭环延迟。
