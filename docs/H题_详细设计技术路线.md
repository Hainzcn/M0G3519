# H题车载平衡滚球运动控制系统 - 详细设计技术路线

版本：V1.0  
日期：2026-07-29  
目标平台：MSPM0G3519 + MaixCam2 + 双轮差速底盘 + 一维摆杆

## 1. 结论与核心决策

### 1.1 摆杆步进电机由谁控制

**摆杆 Emm42 步进电机必须由 MSPM0G3519 直接控制，MaixCam2 不直接输出摆杆驱动指令。**

职责划分如下：

| 模块 | 主要职责 | 不负责的内容 |
| --- | --- | --- |
| MaixCam2 | 采集图像、识别钢球、像素坐标转摆杆坐标、输出测量时间戳/置信度、图传和录像 | 不控制摆杆步进电机，不控制底盘，不参与赛道循迹 |
| MSPM0G3519 | 底盘运动规划、循迹、轮速闭环、车辆加速度前馈、滚球状态估计、摆杆控制、故障降级 | 不做图像处理 |
| 赛道外电脑/PAD | 实时显示、完整录像、调试数据记录 | 不向车发送运动指令 |

选择 3519 控制 Emm42 步进电机的原因：

1. 3519 同时拥有底盘目标速度、加减速曲线、编码器速度和滚球目标位置，可在车辆真正加速前计算前馈。
2. 步进电机、底盘电机和安全状态由同一个控制器管理，能够保证启动、减速、停车和滚球闭环的时序一致。
3. MaixCam2 的图像处理帧率和延迟可能随曝光、图传和算法负载波动，不适合作为最终执行器的唯一实时控制器。
4. MaixCam2 到 3519 的串口传输延迟约 1~2ms，远小于相机曝光/处理延迟和摆杆机构的机械响应时间。省掉该串口并不会带来决定性收益。
5. 通信中断、钢球丢失或 MaixCam2 重启时，3519 可以立即将摆杆回中并让小车受控减速。

### 1.2 推荐总体方案

- 车辆控制器：MSPM0G3519，裸机定时调度。
- 钢球测量：MaixCam2，目标有效测量频率 60~100Hz。
- 视觉通信：TTL UART，V1 默认 115200-8-N-1，24 字节二进制定长帧；
  230400 作为日志量增大后的可选升级。
- 滚球控制计算：3519 上以 200Hz 运行预测器和状态反馈。
- 摆杆位置指令：经 UART7 向 Emm42 发送，默认 100~200Hz；不得假设驱动器可接受无约束的更高刷新率。
- 底盘轮速环：200Hz。
- 循迹方向环：100~200Hz。
- 车辆轨迹规划：100Hz，采用限加速度、限加加速度的 S 曲线。

## 2. 题目约束转化为工程指标

### 2.1 几何和运动指标

- 摆杆有效长度 25cm，坐标范围约为 -12cm 到 +12cm。
- 钢球直径约 1cm，要求位置绝对误差不超过 1cm。
- 小车外形不得超过 35cm x 25cm，摆杆不得超出车身。
- 赛道周长约为 `2 x 1.5 + 2 x pi x 0.5 = 6.14m`。
- 20s 完成一圈要求平均速度不低于约 0.31m/s，还要留出起步和停车时间。
- A 到 B 为 1.5m，8s 指标相对宽松，但要求运动过程中钢球稳定在中心附近。

### 2.2 规则边界

- 小车循迹只能使用红外光电模块，不能将 MaixCam2 的赛道识别结果用于车辆循迹。
- 摄像头必须在车上并覆盖完整摆杆，发送模块固定在车体。
- 图传接收、显示和存储设备位于赛道外，比赛结束后与作品一起封存。
- 运行中不得遥控车辆。
- 钢球和摆杆凹槽内壁不得进行增摩改造。

### 2.3 内部设计目标

正式指标是 1cm，工程上应按更严格目标设计：

| 指标 | 内部目标 | 最低可接受值 |
| --- | --- | --- |
| 静态球位置 RMS 误差 | <= 3mm | <= 5mm |
| 动态球位置峰值误差 | <= 7mm | < 10mm |
| 视觉有效更新率 | >= 80Hz | >= 50Hz |
| 视觉测量丢失率 | < 0.5% | < 2% |
| 测量到控制计算抖动 | <= 2ms | <= 5ms |
| 200Hz 控制任务执行时间 | <= 1ms | <= 2ms |
| 摆杆角度重复性 | <= 0.2deg | <= 0.4deg |
| A 点停车重复误差 | <= 10mm | <= 20mm |

## 3. 系统硬件架构

```text
                   +---------------------------+
                   | 赛道外电脑/PAD            |
                   | 实时画面 + 完整录像 + 日志 |
                   +-------------^-------------+
                                 | Wi-Fi/图传
                                 |
+-------------+  UART测量帧  +---+----------------+
| MaixCam2    | ------------> | MSPM0G3519        |
| 球检测/标定 | <------------ | 视觉链路配置/心跳 |
+------+------+  可选控制帧   +--+----+----+------+
       |                        |     |    |
       | 摄像头                 |     |    +--> OLED/按键/蜂鸣器
       v                        |     +------> Emm42 步进电机 UART7
  25cm摆杆和钢球                +------------> TB6612 + 左右电机
                                 ^      ^
                                 |      |
                            8路红外   双编码器 + IMU
```

### 3.1 现有 3519 资源占用

| 资源 | 当前用途 |
| --- | --- |
| TIMA0 CH0/CH1 | 左右电机 PWM |
| TIMG8/TIMG9 | 左右轮正交编码器 |
| TIMG7 | 灰度通道切换稳定计时 |
| UART0 PA10/PA11 | 调试输出 |
| UART1 PA8/PA9 | IMU |
| UART7 PA23/PA24 | Emm42 步进电机驱动 |
| I2C0 PB0/PB1 | OLED |
| SysTick | 1ms 系统时间基准和电机看门狗 |

新增硬件前必须完成一次完整的定时器、UART 和引脚复用表，禁止边接线边修改资源。

MaixCam2 串口资源优先级：

1. 优先从芯片和核心板可用复用引脚中增加一个独立 UART，保留 UART0 调试和 UART1 IMU。
2. 如果新增 UART 与 Emm42 或现有引脚冲突，比赛模式可将 UART0 改作 MaixCam2 接口；开发模式再接 USB-TTL 输出日志。
3. 不建议让 MaixCam2 和 IMU 共用 UART，也不建议用软件串口承担 100Hz 视觉链路。
4. 在确定新 UART 前，应先在 SysConfig、芯片数据手册和核心板原理图中三方核对引脚。

### 3.2 供电与抗干扰

- Emm42 驱动器与步进电机不得由 3519 核心板的 5V 引脚直接供电。
- 使用独立 12~24V（按驱动器规格）电源，建议持续电流 >= 2A，并保留更高的瞬态余量。
- 步进电机电源入口附近放置 470~1000uF 低 ESR 电解电容和 0.1uF 陶瓷电容。
- 底盘电机、Emm42、3519、MaixCam2 必须共地，采用星形回地或粗地线，避免大电流回流经过 MCU 地线。
- MaixCam2 与 3519 的 GPIO 电平必须确认均为 3.3V；不确定时加入电平转换，不能仅凭接口外观判断。
- UART 线尽量短，TX 与 GND 成对布线，远离底盘电机线和步进电机电源线。

## 4. MaixCam2 视觉设计

### 4.1 图像处理流程

1. 固定摄像头、摆杆和补光结构，禁止自动对焦造成视野变化。
2. 锁定曝光、增益和白平衡，减少金属球反光导致的阈值漂移。
3. 只处理摆杆 ROI，不处理赛道画面。
4. 对 ROI 做透视/畸变标定，将图像横坐标映射到摆杆物理坐标。
5. 使用亮度、圆形/连通域、尺寸范围和运动连续性联合识别钢球。
6. 输出原始物理坐标、置信度和采集时间，不在 MaixCam2 内完成最终 PID。
7. 同一张图像只能发送一次有效测量，不能为了凑 100Hz 重复发送旧坐标。

### 4.2 坐标定义

- 摆杆中心 O 为 `x = 0mm`。
- 面向小车前进方向的一端定义为正方向；安装后通过一次人工移动确认符号。
- 通信使用 0.1mm 为单位的有符号整数，避免跨平台浮点格式问题。
- 标定至少采集 `-120, -100, ..., 0, ..., +100, +120mm` 多个点，使用一次或二次多项式拟合。
- 标定残差应小于 2mm；若边缘误差明显增大，优先做透视校正而不是提高控制增益。

### 4.3 视觉有效性判断

以下任一情况应设置测量无效标志：

- 未检测到候选球。
- 同时检测到多个无法区分的候选目标。
- 球坐标超出物理范围。
- 本帧坐标相对预测位置跳变超过合理速度上限。
- 图像过暗、过曝或 ROI 被遮挡。

MaixCam2 仍应发送无效帧，让 3519 能区分“本帧无球”和“通信中断”。

## 5. MaixCam2 与 3519 通信协议

> **版本说明（2026-07-30）：** 本节 5.1~5.5 的 21 字节格式为早期草案，保留
> 用于设计追溯，不再作为实现依据。当前权威 V1 协议为
> `../../SBDandT/docs/主控通信方案.md`：默认 115200-8-N-1、24 字节视觉状态帧，
> MCU 反向链路为原始日志字节流。开发、测试和验收均以该文档为准。

### 5.1 物理层和频率（历史草案，已废止）

- 接口：3.3V TTL UART，全双工，必须共地。
- 默认波特率：230400-8-N-1。
- 兼容波特率：115200-8-N-1；21字节帧在 100Hz 下约占 18%的链路带宽，仍然可用。
- 推荐测量率：每个新相机帧发送一次，目标 80~100Hz；实际只有 60fps 时就发送 60Hz。
- 3519 不逐帧 ACK，避免反向拥塞。错误率和心跳通过独立状态报文监控。
- UART RX 中断只收字节进入环形缓冲区，协议解析和 CRC 校验在主循环高优先级任务完成。

### 5.2 钢球测量帧（历史草案，已废止）

多字节整数统一为小端。固定帧总长 21 字节：

| 偏移 | 长度 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 2 | SOF | uint8[2] | 固定 `0xA5 0x5A` |
| 2 | 1 | version | uint8 | 协议版本，初始为 `0x01` |
| 3 | 1 | type | uint8 | 球测量为 `0x10` |
| 4 | 1 | payload_len | uint8 | 固定为 14 |
| 5 | 2 | frame_seq | uint16 | 每张新图像递增，回绕允许 |
| 7 | 4 | capture_ms | uint32 | MaixCam2 图像采集时间，毫秒 |
| 11 | 2 | x_0p1mm | int16 | 相对摆杆中心位置，0.1mm/LSB |
| 13 | 2 | y_0p1mm | int16 | 调试用横向位置，0.1mm/LSB |
| 15 | 1 | confidence | uint8 | 0~100 |
| 16 | 1 | flags | uint8 | 见下表 |
| 17 | 2 | process_0p1ms | uint16 | 图像处理耗时，0.1ms/LSB |
| 19 | 2 | crc16 | uint16 | CRC-16/CCITT-FALSE |

CRC 参数：

```text
poly   = 0x1021
init   = 0xFFFF
xorout = 0x0000
refin  = false
refout = false
范围   = version 字段到 payload 最后一个字节，不包含 SOF 和 CRC
```

`flags` 定义：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| bit0 | BALL_VALID | 当前坐标有效 |
| bit1 | ROI_VALID | ROI/标定参数有效 |
| bit2 | EXPOSURE_OK | 曝光处于允许范围 |
| bit3 | MULTI_CANDIDATE | 出现多个候选球 |
| bit4 | FRAME_DROPPED | MaixCam2 检测到图像丢帧 |
| bit5~7 | RESERVED | 固定为 0 |

### 5.3 辅助报文（历史草案，已废止）

- `0x11 VISION_STATUS`：1Hz，发送实际 FPS、累计丢帧、温度和算法状态。
- `0x20 CTRL_CONFIG`：3519 向 MaixCam2 发送开始/停止、标定模式、目标帧率等配置。
- `0x21 CTRL_ACK`：MaixCam2 对配置命令确认；只用于低频配置，不参与逐帧闭环。
- `0x30 DEBUG_MARK`：测试阶段在视频和控制日志中插入同一事件编号，用于对齐延迟。

### 5.4 接收状态机（历史草案，已废止）

1. 搜索 `0xA5 0x5A`。
2. 读取版本、类型和长度，长度非法立即回到搜索状态。
3. 收满 payload 和 CRC 后校验。
4. 校验成功才更新“最新测量”双缓冲；控制器始终读取一份完整快照。
5. 记录 CRC 错误、序号跳变、重复帧、无效帧和最大帧间隔。
6. 发生半帧超时（建议 5ms）时丢弃当前帧并重新同步。

### 5.5 数据新鲜度与降级（历史草案，已废止）

| 最新有效测量年龄 | 控制策略 |
| --- | --- |
| <= 30ms | 正常预测和闭环控制 |
| 30~80ms | 用状态模型短时预测，限制摆杆角度和车辆加速度 |
| 80~300ms | 摆杆缓慢回中，车辆按受控曲线减速 |
| > 300ms | 停车并进入视觉链路故障状态，禁止继续测试 |

相机时间戳主要用于计算相邻图像的真实 `dt`。控制到当前时刻的预测年龄可用 `process_0p1ms + 串口发送时间 + 本地排队时间` 估算；后续再增加双向时钟同步，不应把两颗芯片的绝对毫秒值直接相减。

## 6. 实时调度设计

### 6.1 推荐周期

| 任务 | 周期/触发 | 优先级 | 说明 |
| --- | --- | --- | --- |
| UART RX 入队 | 字节中断 | 最高 | ISR 中禁止解析和打印 |
| 轮速采样与 PI | 5ms / 200Hz | 高 | 固定周期 |
| 球状态预测与摆杆控制 | 5ms / 200Hz | 高 | 新视觉帧到达时校正，其余周期预测 |
| 灰度循迹 PD | 5~10ms | 高 | 只使用红外模块 |
| 车辆 S 曲线规划 | 10ms / 100Hz | 中高 | 生成速度、加速度和前馈预览 |
| 比赛状态机 | 10ms | 中 | 管理启停和各测试模式 |
| OLED | 100~200ms | 低 | 比赛运行时只做单页增量刷新或关闭 |
| 调试日志 | 10~100ms | 最低 | 二进制、限流、允许丢弃 |

### 6.2 调度约束

- 使用专用定时器或 SysTick 派生固定周期任务标志，控制计算不要依赖主循环自然运行频率。
- 中断中只做采样、入队、时间戳和置位，PID、协议解析、显示和日志均放在主循环。
- 每个 5ms 控制周期统计开始/结束时间，记录最大执行时间和超期次数。
- 当前 OLED 整屏刷新约需 25ms，正式运行时禁止整屏刷新。
- 正式运行时禁止高频 `printf/snprintf` 浮点格式化；遥测使用定长二进制结构。
- 底盘电机和 Emm42 输出均设置独立看门狗，控制任务超时立即进入安全值。

## 7. 滚球物理模型与控制器

### 7.1 简化模型

钢球按实心球纯滚动近似，转动惯量为：

```text
I = 2/5 * m * r^2
```

定义：

- `x`：钢球相对摆杆的位置。
- `theta`：摆杆相对车体水平面的倾角，小角度时 `sin(theta) ~= theta`。
- `a_car`：小车沿摆杆轴向的加速度。

忽略摩擦和高阶耦合后：

```text
x_ddot = 5/7 * (g * sin(theta) - a_car)
```

若控制器期望钢球获得相对摆杆加速度 `u`，前馈逆模型为：

```text
theta_cmd = asin((7/5 * u + a_car) / g)
```

实际安装方向可能使符号相反，首次台架实验必须确认坐标、步进电机曲柄和车辆加速度三个正方向，不能直接照搬公式符号。

### 7.2 控制结构

推荐使用“状态估计 + 状态反馈 + 车辆加速度前馈”，而不是单一位置 PID：

```text
位置目标 x_ref
      |
      v
u = Kp*(x_ref-x) + Kd*(v_ref-v) + Ki*integral
      |
      +---- 与 a_car 前馈进入逆模型 ----> theta_cmd
                                            |
                                  Emm42 位置映射/限幅/回差补偿
                                            |
                                   UART7 位置指令
```

控制器要求：

- 位置误差积分只在 `|error|` 较小、视觉有效且输出未饱和时启用。
- 摆杆初始角度限幅建议从 +/-4deg 开始，逐步放宽但不超过机械安全范围。
- 角速度/指令变化率必须限幅，避免机构冲击和钢球失控。
- 钢球接近 +/-10cm 时进入边缘保护，优先回中并降低车速。
- 视觉测量之间由常加速度模型预测 `x` 和 `v`，新帧到达时再校正。
- 初期可使用 alpha-beta 滤波，参数稳定后再决定是否需要二状态卡尔曼滤波。

### 7.3 启动和停车前馈

最有效的前馈不是对编码器微分后再补偿，而是让 3519 预先知道车辆将如何运动：

1. 车辆速度目标由 S 曲线规划器生成，而不是占空比阶跃。
2. 规划器同时输出 `v_ref`、`a_ref` 和未来一个步进电机延迟时间的 `a_ref_preview`。
3. 摆杆前馈优先使用 `a_ref_preview`，让摆杆在底盘加速前或同步开始补偿。
4. 编码器速度微分经过低通后得到 `a_wheel`，用于修正轮胎打滑、电池电压和负载误差。
5. 建议估计 `a_car = w*a_ref_preview + (1-w)*a_wheel_filtered`，初始 `w` 可从 0.7 开始。
6. 若后续增加车体纵向加速度计，只作为低频/可信度修正；振动环境下不能直接使用原始加速度。

停车过程采用“提前减速 - 低速寻找启停线 - 主动刹车 - 位置保持”四阶段，禁止在检测到 A 线后才从全速突然刹车。

### 7.4 步进电机延迟补偿

需要辨识从 UART 位置指令到摆杆实际转动的总延迟 `tau_stepper`。车辆规划器可读取未来 `t + tau_stepper` 的加速度作为前馈。Emm42 驱动器可回读实际位置；若无摆杆角度传感器，至少用 MaixCam2 观察摆杆边缘或临时安装角度标记完成台架辨识；正式识球算法不得因此依赖赛道视觉。

## 8. Emm42 步进电机评估与配置

### 8.1 执行器特点

项目采用 Emm42 闭环步进驱动 + 步进电机，经 UART7 接收位置/速度指令。与 RC 舵机相比：

- 3519 下发的是目标角或脉冲，不是 PWM 脉宽。
- 驱动器内部有位置环，可回读位置和速度。
- 不存在舵机式 50Hz 脉宽刷新限制，但 UART 带宽、帧解析和驱动器加减速能力仍构成实际上限。
- 负载变化时主要体现为跟随误差和允许的最大角速度，而不是脉宽-角度非线性。

因此摆杆控制应围绕“位置指令 + 速率/加速度限制 + 跟随误差监控”设计，而不是 PWM 标定。

### 8.2 台架验收方法

测试时使用正式摆杆、连杆和供电，不能只测空载电机：

1. 标定 `目标角 -> 摆杆角度` 曲线，至少测中心两侧各 8~10 个点。
2. 分别从正、反方向接近相同指令，测量机构回差和 Emm42 跟随误差。
3. 输入 +/-2deg、+/-4deg、+/-6deg 小角度阶跃，记录指令发出时间、10%~90% 上升时间和稳定时间。
4. 以 100Hz 发送位置指令重复测试，再尝试 200Hz；若通信拥塞、丢帧或振荡立即退回较低频率。
5. 连续运行 10min，检查温升、电源跌落、零位漂移和重复性。
6. 用 MaixCam2 录像和事件标记对齐 UART 指令，计算实际控制延迟。

建议验收门槛：

| 项目 | 建议通过值 |
| --- | --- |
| 小角度动作开始延迟 | <= 30ms |
| +/-4deg 阶跃稳定时间 | <= 80ms |
| 双向回差 | <= 0.3deg |
| 重复定位误差 | <= 0.2deg |
| 连续运行零位漂移 | <= 0.2deg |
| 负载运行 | 无明显振荡、掉压和过热 |

这些门槛是工程初始值，应以实际闭环测试结果调整。某一项略超标不代表必然无法完成基础项，但会显著压缩动态控制裕量。

### 8.3 优化顺序

若 Emm42 台架结果未达预期，按以下顺序优化：

1. 调整 Emm42 细分、电流、加速度和最大转速参数，优先保证小角度响应和重复定位。
2. 优化连杆：缩短无效连杆、避免接近几何死点、增加结构刚度。
3. 增加摆杆实际角度传感器，例如磁编码器，让 3519 建立角度内环并修正跟随误差。
4. 只有在 Emm42 仍无法满足时，才考虑更换更大扭矩的闭环步进方案或自制伺服轴。

不建议回退到 RC 舵机方案：脉宽控制、死区/回差和刷新率限制都不利于 200Hz 摆杆闭环。Emm42 已通过 UART7 接入现有工程，应优先完成驱动器参数和机构标定。

## 9. 底盘控制技术路线

### 9.1 双轮速度环

- 两侧编码器固定 5ms 采样，计算增量计数和速度。
- 每侧独立 PI，加入启动最小占空比、输出限幅和抗积分饱和。
- 左右轮速度标定后增加静态增益补偿，减少直线偏航。
- 速度给定来自轨迹规划器，禁止直接把循迹误差映射为无约束 PWM。

### 9.2 红外循迹

- 将 8 路数字量按位置加权计算横向误差。
- 对直线和弯道使用增益调度；弯道主动降低基础速度。
- 短时丢线使用上一次误差和陀螺仪角速度预测，超过阈值立即减速。
- MaixCam2 不提供路线误差，确保满足“只能使用红外光电模块”的规则。

### 9.3 A 点停车

- 使用 5cm 横向启停线的多探头同时触发特征识别 A 点。
- 编码器里程用于预计 A 点到达时间，提前进入低速阶段。
- 根据当前速度标定制动距离表，而不是使用固定延时。
- 检测基准线后执行主动制动，并利用低速短距离修正实现 <= 2cm 停车。

## 10. 比赛功能状态机

```text
BOOT
  -> SELF_TEST
  -> WAIT_MODE
  -> WAIT_START
  -> BALL_PREPARE
  -> RUN_ACCEL
  -> RUN_CRUISE
  -> RUN_DECEL
  -> STOP_HOLD
  -> RESULT_DISPLAY

任意状态发生严重故障 -> FAULT_DECEL -> FAULT_STOP
```

模式定义：

- MODE_2：只循迹一圈并停车，滚球控制可回中但不作为评分目标。
- MODE_3：车辆静止，执行 `O -> +5cm -> -5cm -> 稳定`。
- MODE_4：球目标 O，A 到 B，8s 内完成。
- MODE_5：球目标 O，完整一圈，30s 内完成。
- MODE_6：按键输入任意指定位置，完整一圈保持该位置。

启动按键必须同时启动计时和任务状态机。测试中不接受外部无线控制命令。

## 11. 软件模块规划

建议沿用当前 `hardware / middle / app` 分层：

```text
src/hardware/
  maixcam_hw.c/.h          UART RX/TX、环形缓冲、错误计数
  emm42_hw.c/.h            UART7、位置指令、限幅、安全回中

src/middle/
  maixcam_link.c/.h        帧解析、CRC、序号和超时
  ball_estimator.c/.h      alpha-beta/卡尔曼状态估计
  beam_control.c/.h        状态反馈、前馈、曲柄逆映射
  wheel_speed_control.c/.h 双轮速度 PI
  line_control.c/.h        红外循迹误差和方向环
  motion_profile.c/.h      S 曲线、速度/加速度/预览输出
  telemetry.c/.h           定长二进制日志和限流

src/app/
  competition_app.c/.h     模式选择、任务状态机、安全降级
  calibration_app.c/.h     Emm42、视觉、轮速和停车标定
```

接口原则：

- hardware 层只处理寄存器、引脚和原始数据。
- middle 层不直接依赖显示或按键。
- app 层负责测试流程，不在 app 中复制 PID 或协议解析。
- 所有控制参数集中放在一个配置头文件，并记录单位、范围和标定日期。

## 12. 参数辨识与测试路线

### 阶段 A：接口和安全

验收条件：

- Emm42 独立供电，动作时 3519 和 MaixCam2 不复位。
- UART 连续运行 10min，无 CRC 错误或错误率低于目标值。
- 拔掉 MaixCam2 后 80ms 内开始降级，300ms 内进入停车状态。
- 步进电机指令超限、任务超时和球丢失都能触发安全策略。

### 阶段 B：视觉标定

验收条件：

- 摆杆全范围坐标误差 <= 2mm。
- 80Hz 目标下连续 1min，有效测量率 >= 98%。
- 手动快速滚动钢球时无明显跳点，时间戳单调且序号连续。

### 阶段 C：执行机构辨识

验收条件：

- 完成 Emm42 零位、比例、非线性、回差、速率和延迟记录。
- 确定安全角度、最大转速/加速度和最大角速度。
- 完成 Emm42 参数与机构标定后，再进入整车联调。

### 阶段 D：静态滚球

1. 先只做球位置显示和手动摆杆命令。
2. 加入速度估计和 PD，不加积分。
3. 完成中心保持后再加入小积分消除偏置。
4. 完成 `O -> +5cm -> -5cm`，总时间 <= 5s。
5. 连续重复 10 次，所有最大误差均 < 1cm 后才进入动态测试。

### 阶段 E：底盘

1. 单轮速度环。
2. 双轮直线速度一致性。
3. 低速循迹。
4. 弯道增益调度。
5. A 点检测和停车距离表。
6. 完成 20s 一圈和 2cm 停车重复性测试。

### 阶段 F：车球联合控制

1. 小车架空或直线短距离测试，只验证启动/停车前馈方向。
2. 限制车速 0.1m/s，完成 A 到 B 中心保持。
3. 逐步增加加速度而不是先增加最高速度。
4. 加入步进电机延迟预览和编码器加速度修正。
5. 完成 A 到 B 后再跑整圈；弯道先降速保证不掉球。
6. 最后增加任意目标位置模式。

## 13. 数据记录与验收表

每次测试至少记录：

```text
本地时间、任务状态、视觉序号、视觉年龄、球位置、球速度、目标位置、
摆杆目标角、Emm42 目标角、车辆目标速度、车辆目标加速度、左右轮速度、
灰度误差、Yaw/Wz、CRC错误数、视觉丢帧数、控制超期数、电池电压
```

每组参数至少重复 10 次，报告以下统计量：

- 完成时间均值和最大值。
- 球位置 RMS、95%分位和最大绝对误差。
- 停车偏差均值、最大值和方向性偏差。
- 视觉帧率、最大帧间隔和丢帧率。
- 步进电机最大指令、饱和时间占比和温升。
- 控制周期最大执行时间和超期次数。

调参时一次只改变一类参数，并给每组参数编号。视频文件、控制日志和参数编号必须能对应，以便用于设计报告中的测试结果分析。

## 14. 故障策略

| 故障 | 检测条件 | 响应 |
| --- | --- | --- |
| 球接近摆杆边缘 | `|x| > 100mm` | 摆杆优先回中，车辆限制加速度并减速 |
| 视觉短时丢失 | 30~80ms 无有效帧 | 模型预测，限制控制输出 |
| 视觉中断 | >80ms 无有效帧 | 摆杆回中，车辆 S 曲线减速 |
| 通信完全中断 | >300ms | 停车、显示故障、禁止自动恢复运行 |
| 步进电机饱和 | 连续超限超过阈值 | 冻结积分、车辆减速 |
| 控制任务超期 | 5ms任务连续超期 | 关闭显示/日志，仍超期则停车 |
| 电池欠压 | 低于标定阈值 | 限制加速度并提示更换电池 |
| 灰度丢线 | 超过允许时间 | 保持短时预测并减速，随后停车 |

## 15. 实施优先级

1. 完成 Emm42 台架测试和供电整改。
2. 完成 MaixCam2 物理坐标输出及 100Hz 二进制协议。
3. 在 3519 上增加固定 5ms 控制调度和通信新鲜度监控。
4. 完成静态滚球第3项。
5. 完成轮速环、循迹和第2项停车。
6. 增加 S 曲线、车辆加速度前馈和第4项。
7. 扩展整圈第5项。
8. 最后实现任意目标位置第6项。

在第3项静态滚球尚未连续通过、Emm42 尚未完成台架验收之前，不应直接开始整圈联合调参。
