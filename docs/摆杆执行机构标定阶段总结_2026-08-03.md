# 摆杆执行机构标定阶段总结

日期：2026-08-03  
状态：阶段性结论，供后续重构继续使用  
关联方案：`摆杆控制重构方案V2.md`

## 1. 文档目的

本文固定截至 2026-08-03 已完成的三项摆杆执行机构标定结果：

1. Emm42 位置模式阶跃响应；
2. Emm42 速度模式、驱动参数和位置轮询稳定性；
3. 电机绝对位置与摆杆实际角度的连杆反解标定。

本文同时记录已经排除的误判、坐标约定、安全边界和后续待办。后续修改控制器前应先阅读本文，避免从零散会话或中途日志重新推断。

## 2. 当前最重要结论

1. **没有证据表明步进电机存在 70 ms 的纯死区。** 旧分析中的约 70 ms 是达到最终位移 5% 的时间，混入了驱动器加速度斜坡和检测阈值，不能直接写入 `BALANCE_ACTUATOR_DELAY_MS`。
2. 最新 56 次 0.5° 电机步进叠加结果表明，编码器约在命令后 20 ms 已出现明确变化；纯启动延迟在当前 20 ms 查询分辨率下只能认为是 0~20 ms 量级。
3. 执行器完整动态不可忽略：电机位置约 80 ms 到达 50%、140 ms 到达 90%；摆杆 IMU 约 80 ms 到达 50%、180 ms 到达 90%。后者还包含 IMU 内部滤波和小信号检测延迟。
4. “狂暴模式”不适合当前机构：虽然上升更快，但超调和稳定时间显著恶化。
5. 12 V 下的保守运动参数响应平滑、无明显超调。速度模式可以使用，但尚未显示出足以替代位置模式的优势。
6. 100 Hz 电机位置查询曾导致程序停止响应。当前策略是测试运动期间最多 50 Hz 查询，并在终点保持后停止查询；UART3 遥测仍可保持 100 Hz。
7. 连杆二次反解拟合质量良好，`R²=0.999538`。临时标定 IMU 与量角器物理角方向相反，且存在约 3.47° 安装零偏；运行控制不依赖该 IMU。

## 3. 坐标和符号约定

本次连杆标定使用以下坐标：

- `m`：下机械限位清零后的 Emm42 有符号绝对位置，抬升摆杆时为负；
- `theta_imu`：UART3 V4 中已经翻转后的 IMU pitch；
- `theta_phys`：量角器定义的摆杆物理角度；
- 下机械限位：`m=0°`，`theta_imu≈+4.03°`，`theta_phys≈-7.50°`；
- `theta_imu` 与量角器物理角方向相反，安装零偏幅值约为 `3.47°`。

换算关系：

```c
theta_phys = -theta_imu - 3.47f;
```

注意：IMU 仅用于本次离线标定，不接入运行时摆杆控制。运行代码直接使用量角器物理角与下限清零后的 Emm42 绝对位置模型。

## 4. 标定一：位置模式阶跃响应

### 4.1 测试范围

- 无球台架测试；
- 摆杆目标阶跃：±1°、±2°、±4°；
- UART3 以约 100 Hz 记录目标和电机位置；
- 代表日志：`log/session_c281dbb4_00/`。

### 4.2 旧阶跃分析结果

| 指标 | 结果 |
|---|---:|
| 有效阶跃 | 28 |
| 5% 起动判据中位数 | 70 ms |
| 5% 起动判据范围 | 50~90 ms |
| 10%~90% 上升时间中位数 | 120 ms |
| 稳定时间中位数 | 630 ms |
| 超调中位数 | 0.1% |
| 最大超调 | 6.6% |

±2°/±4° 阶跃的典型稳定时间约为 200~720 ms。小阶跃的稳定时间容易被编码器噪声和 2% 稳定带判据放大，因此不应单独据此判断执行器很慢。

### 4.3 对“70 ms 延迟”的修正

旧分析器把响应达到最终位移 5% 的时刻命名为 `onset_delay_ms`。这个命名容易被误解为纯死区，实际包含：

- MCU 发命令和 Emm42 接收；
- 驱动器内部控制周期；
- 加速度从零建立；
- 编码器位置查询与回包；
- 位置必须越过 5% 阈值。

在 115200 baud 下，13 字节位置命令在线路上的发送时间约 1.1 ms，本身不可能解释固定 70 ms 延迟。

使用最终连杆标定日志中的 56 次有效 0.5° 步进重新叠加，得到：

| 响应进度 | 电机编码器 | 摆杆 IMU |
|---|---:|---:|
| 首次明确变化 | 约 20 ms | 约 50~60 ms |
| 50% | 约 80 ms | 约 80 ms |
| 90% | 约 140 ms | 约 180 ms |

IMU 响应晚于编码器还包含 100 Hz 报告周期、姿态滤波、连杆间隙以及单步摆角变化仅约 0.1~0.2° 的信噪比限制。

当前应采用的执行器模型是：

```text
纯启动延迟：尚未精确辨识；当前观测上界约 20 ms
执行器动态：加速度/速率受限，约 80 ms 到 50%，140~180 ms 到 90%
```

**禁止继续把 70~80 ms 直接当作纯延迟参数。** 若控制代码需要临时值，`BALANCE_ACTUATOR_DELAY_MS` 可从约 20 ms 起步，但必须把后续斜坡作为执行器动态或命令整形的一部分处理。

## 5. 标定二：速度模式和驱动参数

### 5.1 狂暴模式对比

关闭和打开狂暴模式的代表日志分别为：

- 关闭：`log/session_c2bf890e_00/`
- 打开：`log/session_c2c0b983_00/`

| 模式 | 10%~90% 上升时间中位数 | 超调中位数 | 稳定时间中位数 |
|---|---:|---:|---:|
| 关闭 | 160 ms | 2.8% | 320 ms |
| 打开 | 110 ms | 32.3% | 850 ms |

结论：狂暴模式约缩短 50 ms 上升时间，但超调和稳定时间明显恶化，不适合当前摆杆机构和控制目标。

### 5.2 12 V 保守参数结果

代表日志：`log/session_c2e6e183_00/`。

| 指标 | 结果 |
|---|---:|
| 有效阶跃 | 28 |
| 5% 判据中位数 | 80 ms |
| 10%~90% 上升时间中位数 | 280 ms |
| 稳定时间中位数 | 580 ms |
| 超调中位数/最大值 | 0% / 0% |

该组结果较慢但平滑，说明 12 V 和保守轨迹能够稳定跟随。速度模式是否用于最终控制仍需和 MCU 权威轨迹方案一起决定：

- 若 MCU 生成唯一摆角轨迹，速度模式可作为轨迹执行接口；
- 若继续使用 Emm42 位置模式，则 MCU 不应再叠加一套与驱动器冲突的未知加速度整形；
- 两套轨迹整形必须二选一，不能串联后再把总效果当成纯延迟。

### 5.3 已发现的通信和安全问题

1. 100 Hz 位置轮询下出现过程序停止响应；不能用 100 Hz 查询作为长期运行方案。
2. 连续速度/相对运动测试出现过目标角逐步漂移，最终触碰机械边界。所有速度模式必须同时维护绝对位置估计和硬限幅。
3. 查询无回包时当前代码不是同步永久等待，但过密查询可能清空接收缓存、覆盖未处理回包或造成总线/解析压力。
4. 建议运行策略：运动期间 20 ms 查询一次；终点保持后停止查询；发送下一查询前应进一步增加“上次请求已完成或超时”的门控。

## 6. 标定三：连杆反解公式

### 6.1 测试方法

- 启动等待 60 s，使安装在摆杆头部的 IMU 收敛；
- 下机械限位设为电机绝对零位；
- 先采集 1 s 零点基线；
- 电机每次沿抬升方向增加 0.5°，保持 1 s；
- 扫描到 -30° 后保持；
- UART3 V4 以 100 Hz 发送电机目标、实测位置和已翻转 IMU pitch；
- 电机位置只在扫描期间以 50 Hz 查询，终点停止查询；
- 最终日志：`log/session_c3924f1d_00/`。

### 6.2 数据质量

| 指标 | 结果 |
|---|---:|
| 有效稳态点 | 61 |
| 电机目标范围 | 0°~-30° |
| 原始标定 IMU 范围 | +4.05°~-5.76° |
| 电机跟踪误差中位数 | 0.04° |
| 最大 IMU 稳态峰峰值 | 0.12° |
| 二次反解 RMSE | 0.189° 电机角 |
| 二次反解最大误差 | 0.944° 电机角 |
| R² | 0.999538 |

最大拟合误差位于下机械限位点。首个 -0.5° 命令的电机实测位置仅约 -0.22°，说明零位附近存在小范围回差、闭环死区或分辨率影响。全局二次曲线不能同时严格穿过该端点并保持中段最低误差。

### 6.3 原始 IMU 坐标下的命令反解

```c
m = -0.154232927f * theta_imu * theta_imu
    +2.716192051f * theta_imu
    -9.385334752f;
```

有效范围：

```text
theta_imu: -5.76° ~ +4.05°
m:         -30.00° ~ 0.00°
```

### 6.4 加入量角器零偏后的物理角命令反解

量角器测得下机械限位约 -7.5°，对应已翻转的标定 IMU 约 +4.03°：

```c
theta_phys = -theta_imu - 3.47f;
```

推荐保留平移形式，减少坐标误用：

```c
float theta_fit = -theta_phys - 3.47f;

m = -0.154232927f * theta_fit * theta_fit
    +2.716192051f * theta_fit
    -9.385334752f;
```

展开后：

```c
m = -0.154232927f * theta_phys * theta_phys
    -3.786568564f * theta_phys
    -20.667624420f;
```

补偿后的物理角有效范围约为：

```text
theta_phys: -7.52° ~ +2.29°
```

按全局拟合曲线，物理水平角 `theta_phys=0°` 对应 `m≈-20.67°`。

这里的有效范围是本次扫描数据覆盖范围，不等同于机械极限声明。二次式在该范围内经过实测验证，范围外只能视为未经验证的外推。

### 6.5 仅用于交叉检查的直接反馈拟合

直接回归 `theta_phys=f(m)` 得到：

```c
theta_phys = -0.005548909f * m * m
             -0.493214484f * m
             -7.723606809f;
```

该直接拟合的摆杆角 RMSE 约 0.117°、最大误差约 0.304°。它可用于日志交叉检查，但运行时最好让命令和反馈共享同一套物理模型及其解析反解，避免两条独立拟合曲线彼此不一致。

固件当前行为：

```text
上电等待 5 s
```

## 8. 尚未完成的辨识

### 8.1 小球动力学计时初步结果

在视觉模块尚未接入时，使用 240 fps 视频测量小球从静止释放到脱离管口的时间。实测球心滚动行程按 0.245 m 计算：

| 物理坡度幅值 | 时间 | 等效加速度 |
|---:|---:|---:|
| 2° | 1.5625 s | 0.200704 m/s² |
| 3° | 1.2236 s | 0.327278 m/s² |
| 4° | 0.9950 s | 0.494937 m/s² |

按 `a = k g sin(|alpha|) - a_f` 回归得到：

```text
k = 0.860739440
a_f = 0.100748322 m/s²
R² = 0.993500516
```

`k` 高于实心球纯滚动理论值 `5/7`，但低于纯滑动上限 1，可作为当前管道、钢球和释放方法下的经验等效参数。可能原因包括局部滑动、球心有效行程误差和视频释放/离管判帧误差。后续应在每个角度增加重复试次，检查参数稳定性。

当前已将 `k` 写入估计器及动力学反解，将 `a_f` 写入现有低速摩擦补偿；尚未把摩擦无条件加入状态预测，因为摩擦方向必须由可靠球速决定。

## 9. 下一步建议

1. 运行当前 V5 Demo，在 2°、3°、4° 各采集至少三次有效释放，检查 `ball_dynamics_summary.txt` 中的逐试次轨迹 R² 和最终 `k/a_f` 回归质量。
2. 若某角度释放距离不足、撞端点过早或视觉丢失，先调整人工释放位置和分析截取范围，不要直接修改动力学模型。
3. 如需复测执行链延迟，可临时安装 IMU 或外部角度计；它们只用于标定，不接入运行控制。
4. 根据较大阶跃决定执行器采用“纯延迟 + 一阶/限加速度模型”还是直接按 MCU 权威轨迹预测，不要把完整上升时间当成纯延迟。
5. 完成静摩擦角、`v_creep` 和制动能力标定，然后再实现 S 曲线前馈、Smith 预测和在线制动抛物线。
6. 恢复正常控制前关闭标定 Demo；保留机械绝对边界和查询门控。

## 10. 禁止重新引入的误判

- 不要把 `onset_delay_ms≈70 ms` 写成电机纯延迟；
- 不要在 100 Hz 持续发送位置查询；
- 不要让速度模式通过相对增量无限累积而没有绝对限位；
- 不要把临时 IMU 当作运行时摆杆反馈；物理角换算必须同时处理方向和零偏；
- 不要把标定坐标的符号直接等同于控制器逻辑符号；
- 不要在实测角度范围外外推当前二次曲线；
- 不要同时保留 MCU 和 Emm42 两套互不透明的轨迹整形。
